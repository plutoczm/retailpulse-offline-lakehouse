# 面试问答

## 1. 为什么做这个项目？

这个项目模拟电商零售平台的离线湖仓建设，从数据生成、数仓分层、Spark 批处理、指标建设到数据质量检查形成完整闭环，能展示我对大数据开发项目的端到端理解。

## 2. 为什么要做数仓分层？

分层能把原始数据、清洗明细、公共维度、主题汇总和应用指标分开，降低耦合。上游变化时可以局部重跑，指标复用也更清楚。

## 3. ODS、DWD、DWS、ADS 有什么区别？

ODS 保留源数据结构；DWD 做清洗后的明细事实；DWS 按业务主题做复用型汇总；ADS 面向看板和具体分析场景输出最终指标。

## 4. DIM 层的作用是什么？

DIM 层沉淀用户、商品、店铺、品类、日期等公共维度，让不同指标使用一致的分析口径，减少重复加工。

## 5. 事实表和维度表怎么划分？

事实表记录业务过程和度量值，例如订单金额、支付金额、退款金额、库存变动数量。维度表记录描述性属性，例如用户城市、商品品类、店铺类型。

## 6. 订单表和订单明细表为什么分开？

订单表是一笔订单粒度，订单明细是一笔订单中的商品行粒度。拆开后既能算订单指标，也能算商品、品类销售指标。

## 7. GMV 口径怎么定义？

本项目 GMV 定义为提交订单的应付金额总和，不要求支付成功。它反映业务交易规模，而不是实际收入。

## 8. 支付金额和 GMV 的区别是什么？

支付金额只统计支付成功流水，GMV 统计下单金额。两者差异来自未支付、取消、支付失败等情况。

## 9. 支付转化率怎么算？

支付转化率 = 支付成功订单数 / 下单订单数。分子和分母都按 `order_id` 去重，避免订单明细多行导致重复。

## 10. 客单价怎么算？

客单价 = 支付金额 / 支付成功订单数。它表示每笔支付订单的平均金额。

## 11. 退款率怎么算？

本项目采用金额退款率：审核通过退款金额 / 支付成功金额。它更直接体现退款对收入的影响。

## 12. 复购率怎么算？

当前口径是日内复购率：统计日内支付成功订单数大于等于 2 的用户数 / 支付用户数。也可以扩展为 30 日复购率。

## 13. 留存怎么算？

以某天活跃用户为 cohort，观察这些用户在第 1 天或第 7 天是否再次活跃。留存率 = 留存用户数 / cohort 用户数。

## 14. RFM 怎么做？

R 是最近一次支付距离统计日期的天数，F 是支付频次，M 是支付金额。根据三个分数把用户划分为高价值、潜力、流失风险和一般用户。

## 15. 为什么使用 Spark 做批处理？

Spark 适合处理大规模离线数据，支持 DataFrame API 和 SQL，能通过分布式计算完成清洗、聚合、join 和窗口排序。

## 16. Spark SQL 执行流程是什么？

SQL 会被解析成逻辑计划，经过 Catalyst 优化器做规则和成本优化，再生成物理计划，最后由 Spark 执行任务。

## 17. 什么是窄依赖和宽依赖？

窄依赖是子分区只依赖少量父分区，例如 map、filter。宽依赖是子分区依赖多个父分区，通常会触发 shuffle，例如 groupBy、join。

## 18. 什么是 shuffle？

shuffle 是数据按 key 重新分布的过程，常见于聚合、排序和 join。它会产生网络和磁盘 IO，是 Spark 性能优化重点。

## 19. broadcast join 适合什么场景？

适合小表和大表关联，例如商品维表、店铺维表和订单明细关联。把小表广播到 executor，可以避免大规模 shuffle。

## 20. cache 和 persist 用在哪里？

本项目在订单明细、支付流水等被多个 DWS 聚合复用的 DataFrame 上使用 `persist`，避免重复扫描和重复计算。

## 21. 为什么使用 Parquet？

Parquet 是列式存储，支持压缩、列裁剪和谓词下推，适合离线分析，比 CSV 更适合作为数仓存储格式。

## 22. 为什么按 dt 分区？

离线任务通常按天跑，`dt` 分区可以减少扫描范围，支持单日重跑，也方便检查分区是否缺失。

## 23. 小文件怎么处理？

本地项目输出前使用 `coalesce` 控制文件数量。生产环境可以使用 compaction、合理分区数、动态分区写入和表格式能力治理小文件。

## 24. 数据倾斜怎么解决？

先定位倾斜 key，再根据场景使用 broadcast join、salting、两阶段聚合、热点 key 单独处理、调大 shuffle partitions 等方式。

## 25. 数据质量怎么做？

本项目检查主键重复、关键字段为空、金额异常、支付时间、退款金额、维表关联、分区完整性、事件枚举和库存数量关系，并输出 Markdown 报告。

## 26. 如果数据量扩大到亿级怎么办？

迁移到集群模式，存储使用 HDFS/S3/MinIO，计算使用 Spark 集群，任务按天增量，热点 key 做倾斜治理，并引入 Delta/Iceberg/Hudi 做表管理和 compaction。

## 27. DWD 层为什么不直接聚合指标？

DWD 保持明细粒度，方便复用和追溯。指标聚合放在 DWS/ADS，能避免明细层过早绑定某个报表口径。

## 28. 为什么 DWS 还需要存在？

DWS 是面向主题的中间汇总层，能复用给多个 ADS 指标，减少重复计算。例如交易日汇总可以同时支撑 GMV、支付转化率、退款率。

## 29. 商品 TopN 怎么避免重复计算？

先在 DWS 按商品和日期聚合销售额，再在 ADS 用窗口函数排名，避免直接在订单明细上反复排序。

## 30. 库存周转率怎么解释？

库存周转率 = 销售数量 / 平均库存。它衡量库存被销售消耗的速度，过低可能说明滞销，过高可能存在缺货风险。

## 31. 项目最大难点是什么？

最大难点是把业务过程、数仓分层和指标口径对齐。代码能跑只是基础，真正重要的是每个指标都能解释清楚来源、粒度和边界。

## 32. Windows 本地如何保证可运行？

项目默认使用 Python + PySpark 本地模式，提供 Makefile、PowerShell 和 Python 一键脚本。Docker 只是可选增强，不作为最小运行依赖。

## 33. 如何处理订单金额与明细金额不一致？

质量检查中会验证订单金额关系。生产环境可增加订单头金额和明细汇总金额对账，异常数据进入隔离表或告警。

## 34. 为什么支付时间不能早于下单时间？

业务流程上必须先下单再支付。支付时间早于下单时间通常说明源系统时间异常、时区不一致或数据关联错误。

## 35. 这个项目可以怎么写进简历？

可以写成：独立设计并实现电商零售离线湖仓项目，使用 PySpark 构建 ODS/DWD/DIM/DWS/ADS 分层，产出 GMV、支付转化率、复购、留存、RFM 和库存周转等指标，并实现数据质量校验和性能优化。
